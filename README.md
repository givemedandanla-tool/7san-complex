# BetterGI 角色邀約全自動・四智能策略

沿用原版「角色邀約全自動」的傳送、購函、兩段對局與繼續挑戰流程，加入四套智慧牌手、遊戲牌組名稱及策略排序。確認敗北才換下一套；獲勝後退出並繼續原版下一段、下一輪。

## 下載與使用

**[下載 InvitationFallback-0.4.3.zip](downloads/InvitationFallback-0.4.3.zip?raw=true)**（約 4.7 MB）。在檔案頁也可按「Download raw file」。[ZIP SHA-256](downloads/SHA256SUMS)。

解壓後將 `InvitationFallback` 放到 BetterGI `User/JsScript/`，在調度器設定原版「挑戰人數、持有邀請函數量」，再填各牌組名稱與排序即可。**不用填對手姓名、難度或先進準備頁。**

0.4.0 依使用者釐清還原原版購函邏輯，欄位忠實顯示「持有邀請函數量（已邀請角色也算）」；填 `0` 首輪會買一張，沒有額外購函開關。智慧牌手單局超時改成手動輸入正整數分鐘，輸入 `120` 就以 120 分鐘為上限。

0.4.3 補上使用者截圖確認的角色邀約入口：辨識右上角「當前牌組」及「先調整一下卡組」，先點調整，進入卡組一覽後才搜尋。持續向右拖，等名稱穩定；連續兩次拖動後第一個名稱及可見清單都不變，才認定到最左。再以小幅、重疊的向左拖動逐段對照名稱，選擇後等待 4 秒，回到對話確認右上角牌組名稱，才點「進行七聖召喚的對局吧」。

這批回報確實是 **0.4.2**：原來的「確認前」其實讀到角色受邀進場，之後已在右上角顯示「當前牌組：我的牌組」的 NPC 對話，並非七日歷練的卡桌準備頁。先前只補局部 OCR、沒有調整卡組入口，因此仍會按預設對話進局。本版在進場轉換後等待可辨識頁面，已接管邀約對話時不再送出原本固定確認點擊；尚未選好牌組時也不按空白鍵／F 選預設開局。保留原版傳送、購函、兩段與賽後續跑流程。

升級請**替換整個套件資料夾**，啟動日誌應顯示「邀約腳本版本 0.4.3」。`牌組查找頁數` 仍控制搜尋範圍；每頁約四組，使用重疊小拖動掃描。回到最左的判斷獨立執行，不以固定拖動次數假定成功。舊版保存的整頁拖動座標不會用作本版的小幅搜尋。

保留 BUG 2 修正：完整執行原版「邀約對局／確認」，認真勝負鎖定而仍處於友好對局時，不會因尚未出現牌組準備頁而提前停止。[原版 197 行逐行分析與根因](docs/UPSTREAM_LINE_REVIEW.md)。

依使用者要求，另於 2026-10-23 重新核對上游 `main`，完成[原版全部 247 行逐行用途報告](docs/ORIGINAL_INVITATION_LINE_BY_LINE.md)：包括主程式、設定、manifest、未被使用的路徑檔、兩張辨識模板及對話等待時間。本次只新增分析文件，沒有改動整合版程式或重新發布套件。

例如排序 `雷柯刻,伊嘉早`：每段先打雷柯刻，輸了換伊嘉早；獲勝後繼續下一段，重新從雷柯刻開始。全部策略仍輸則記錄該段失敗，再按原版繼續。技術錯誤或結果不明會停止。

完整環境要求、牌表及運行步驟見[套件說明](src/InvitationFallback/README.md)。遊戲使用簡體中文及 1920×1080，BetterGI 0.66.0+。目前通過離線測試與原版操作軌跡比對，尚未在遊戲內實測。

0.1.0～0.4.2 僅保留作歷史下載，請改用 0.4.3。

## 開發與打包

需求：Node.js 22+、Python 3.10+，沒有 npm 外部依賴。

```sh
npm run build
npm test
npm run check
```

產物：`dist/InvitationFallback-0.4.3.zip`。`downloads/` 保存對應可安裝成品及校驗碼。

`vendor/` 保存固定版本的原邀約腳本、四套牌手及素材，依 `vendor/lock.json` 校驗。`tools/build.py` 由原版產生導航接入層和牌手工廠，保留原有主流程與牌手決策；建置及執行均無需下載遠端程式。

`tests/original-flow.test.cjs` 對照原版實際原始碼，驗證多輪、不同邀請函數量下的按鍵、點擊與等待序列，並測試四策略重試、兩段與下一輪續跑。另有牌手載入、UI 選牌及購函確認測試。離線模擬不等同遊戲實測。

`tests/invitation-regression.test.cjs` 使用實際 UI、流程及生成導航，模擬鎖定認真勝負、邀約頁沒有牌組控制項、確認或對話後才出現準備頁，並驗證先選牌再出首手牌、原版購函排程及賽後不誤開新局。這些畫面邊界是 0.2.0 原測試未涵蓋的部分。

`tests/custom-timeout.test.cjs` 載入四套真實牌手，以虛擬時鐘驗證 120 分鐘確實進入單局計時器、20 分鐘不提前超時、到期拋錯並釋放資源。

`tests/weekly-deck-ocr.test.cjs` 驗證局部牌組名稱、第四格、OCR 更正與名稱確認；邀約回歸涵蓋本次進場／NPC 對話入口、從卡組中段起始、拖動卡頓及部分卡片偏移、慢速 OCR、左邊界確認、非首屏名稱、敗北後換策略、名稱錯誤與缺少調整選項時不開局。公開樣本只保留必要 UI 文字，已移除 UID 與玩家姓名。68 項離線測試通過，仍需遊戲試跑驗證實際操作。
