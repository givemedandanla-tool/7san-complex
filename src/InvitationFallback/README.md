# 七聖角色邀約全自動・四智能策略 0.4.0

沿用柒葉子原版「角色邀約全自動」的運行路線與外層循環，只在開局前加入按牌組名稱換牌、在打牌處接入四套智慧牌手，並在確認敗北後依排序換策略重打。**打贏後會沿原版退出、對話，繼續下一段與下一輪。**

此版已做離線測試與原版操作順序比對，**尚未在原神／BetterGI 遊戲會話實測**。

0.4.0 還原原作者的購函條件與數量欄位文字，移除額外購函開關；智慧牌手單局超時可手動輸入分鐘。保留先前 BUG 2 修正，完整執行選角、點邀約對局與確認後，才在實際準備頁換牌。[原版全部 197 行審查與問題根因](../../docs/UPSTREAM_LINE_REVIEW.md)。

## 安裝與啟動

1. 使用 BetterGI 0.66.0 或以上，遊戲語言設為**簡體中文**，實際遊戲客戶區設為 **1920×1080**。渲染精度建議 1.0，至少符合原牌手要求 0.8。
2. 解壓 `InvitationFallback-0.4.0.zip`，將整個 `InvitationFallback` 資料夾放到 `BetterGI/User/JsScript/`。確認路徑為 `User/JsScript/InvitationFallback/manifest.json`。
3. 升級時替換原本同名套件；若要保留先前日誌，先備份 `data/` 與 `engines/*/logs/`。在調度器重新開啟自訂配置，檢查持有數量、策略順序與手動超時設定。舊版保存的自動購函開關不再使用。
4. 在調度器新增此 JS，填好挑戰人數、邀請函數量、牌組名稱和策略順序，啟動即可；入口與原版相同，由腳本返回主介面、傳送貓尾並走到邀請板。**不需要填對手名字、難度，也不用先手動進準備頁。**

四套牌手與素材已完整包含，不需另外訂閱，不需開啟 HTTP。請先設好 BetterGI 的停止按鍵，執行時讓腳本操作鍵鼠。

## 設定範例

假設你想先用雷柯刻，輸了才改用伊嘉早：

| 設定 | 範例與意義 |
|---|---|
| 挑戰人數 | `1`：沿用原版的一輪，依序執行兩段對局 |
| 持有邀請函數量（已邀請角色也算） | 依原版語意填寫；`0` 表示持有零張，首輪會先買一張；只跑一輪且目標已邀請，可填 `1` |
| 策略應用順序 | `雷柯刻,伊嘉早`：只用這兩套；可任意改變排列 |
| 雷柯刻牌組名稱 | `甲隊`：與你遊戲內該套牌組的名稱一致 |
| 伊嘉早牌組名稱 | `乙隊`：與遊戲內名稱一致 |
| 牌組查找頁數 | 預設 `2`；第一次建議將要用的牌組放第一頁 |
| 智能牌手單局超時（分鐘） | 手動輸入正整數，例如 `120`；預設 `15` |

預設排序是 `雷柯刻,伊嘉早,月绽放,莫早卢`。只保留自己已備好的策略即可，每段最多將排序內各策略嘗試一次；沒有另外的「最多三場」限制，第四套也能被使用。

**每一套都必須先在遊戲內建好完整牌組，名稱應唯一且使用容易 OCR 辨識的字。** 套件只選擇牌組，不會自動組牌、導入分享碼或購買卡牌。辨識牌手需要下表指定角色順序和原牌表；不會完整盤點遊戲中的行動牌。

| 排序中填入的名稱 | 角色從左到右 | 完整牌表與分享碼 |
|---|---|---|
| 雷柯刻 | 雷電將軍／柯萊／刻晴 | [牌組說明](../../vendor/players/RaidenColleiKeqingPlayer/README.md) |
| 伊嘉早 | 伊安珊／嘉明／早柚 | [牌組說明](../../vendor/players/IansanGamingSayuPlayer/README.md) |
| 月绽放 | 菈烏瑪／哥倫比婭／奈芙爾 | [牌組說明](../../vendor/players/MoonbloomPlayer/README.md) |
| 莫早卢 | 莫娜／早柚／迪盧克 | [牌組說明](../../vendor/players/MonaSayuDilucPlayer/README.md) |
| 原固定策略 | 對應 BetterGI 七聖設定中選好的文字策略 | 使用 BetterGI 原本的 `AutoGeniusInvokation`；另填對應牌組名稱 |

起手處理沿用原牌手支援的選項。單局超時可輸入任意可安全換算的正整數分鐘，例如 `1`、`30`、`120`；輸入 `120` 會傳入四套牌手的實際計時器，到達上限時拋出超時錯誤並停止，不當成敗北換策略。每局重新計時。

此欄位只控制四套智慧牌手自初始手牌入口開始的單局時間；原固定文字策略使用 BetterGI 原有行為，傳送、對話及準備頁的短等待維持原設定。原牌手的動作次數上限、技術錯誤及手動停止仍有效，出牌決策和辨識門檻不變。

## 打完後怎麼繼續

外層流程直接由固定版本的原版腳本產生，順序如下：

1. 返回主介面、傳送貓尾。
2. 按原版 `letterNumber <= i` 判斷是否購買一張，成功後本次持有數加一。首輪 `i = 0`，所以填 `0` 會先買；每輪只判斷一次。
3. 執行原版 `gotoBoard1` 和完整 `chooseCharacter`：開板、選第一格、點原頁籤、點邀約對局及確認。只有實際看到出戰牌組準備頁才接入換牌組，不要求邀約頁已經有準備頁控制項。
4. 若確認敗北，沿原版退出及對話，重新執行本段的選角／頁籤／開局步驟，換排序下一套；不重新傳送、買函或走到另一段。
5. 一旦獲勝，沿原版 `Playcards` 的退出與對話步驟收尾，接著執行 `gotoBoard2`，**重新從排序第一套開始**第二段對局。
6. 第二段結束後，照原版進入下一輪，直到達到「挑戰人數」。

原版兩段都呼叫同一套固定座標的選角函式，本版保留其行為，沒有另加下一位搜尋、翻頁或雙難度掃描。角色和頁籤如何隨遊戲畫面推進，與你指定的原版版本一致。

認真勝負未解鎖時，不把它當成停止條件；原版點鎖定頁籤後仍留在友好對局的路徑會繼續執行。原碼沒有明確的鎖頭辨識，本版也不宣稱靠鎖頭判斷已選難度。

換牌組的觀察點放在原版邀約開始與確認點擊之前，以及進局前對話中。當下仍是邀約頁就繼續原動作；若準備頁在確認或對話後才出現，便於那時選牌，再按該頁實際可見的開始按鈕。若直到初始手牌仍未確認所選牌組，會停止並回報 `DECK_SELECTION_TOO_LATE`，避免用錯牌手。

若本段所有已出戰策略都輸且最後一局已完成原版退出與對話，會記錄「未獲勝」，再依原版繼續下一段／輪；最後報告實際勝敗段數。這不會把敗北當作完成挑戰目標。找不到的牌組會在開局前跳過；若剩餘牌組全找不到，會停在準備頁回報，不在選單中繼續執行走位。

只在已確認敗北時換策略。對局結果不明、停止任務、程式錯誤或重開後邀約詳情不一致都會停止，保留診斷資料，不當成普通敗北。

## 邀請函與介面辨識

- 欄位固定顯示「持有邀請函數量（已邀請角色也算）」，數量由你填寫，原版不讀取遊戲庫存或逐一判斷角色是否已邀請。填 `0` 首輪買；填 `1` 可覆蓋第一輪，依此類推。
- 沒有額外購函開關；0.3.0 加入的開關已依使用者要求移除，舊設定值會忽略。**輸了重試不會觸發購買**，補買僅在原版每輪開頭處理。
- 沿原購買路線只買一張；提交前確認邀請函窗口及數量，寫入待確認紀錄，看到購買成功後才繼續原路線。
- 若 `data/purchase-pending.json` 仍為 `pending: true`，表示購買結果未確認。先核對遊戲庫存、更新「持有邀請函數量」；確認交易已處理後，才可清除此檔，避免重複購買。
- 重試會比對已觀察到的邀約詳情上方 OCR 文字，與上一局不一致或無法辨識時停止。固定座標與區域可在 `ui-profile.json` 調整。

## 執行紀錄與問題回報

- `data/last-run.json`：每輪、每段、牌組、策略及勝敗；最終結果 `completed_with_losses` 表示原版路線已跑完但有段落未獲勝。
- `data/last-error.json`：停止原因及 OCR 文字與座標。
- `data/last-error.png`：可關閉的本機現場截圖，可能包含 UID，回報前請遮蔽。
- `engines/<牌手>/logs/`：原牌手詳細日誌。

首次建議只設 `1` 人、使用兩套已備好牌組，觀察第一段結束後是否能走到第二段。若停下，提供停止訊息與已遮蔽的診斷資料即可。獲勝以「对局胜利」為準，不代表額外挑戰目標全數完成。
